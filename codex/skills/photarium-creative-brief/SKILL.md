# Photarium Creative Derivation

The versioned source for this skill lives in `codex/skills/photarium-creative-brief/`. After changing it, synchronize the installed global copy with:

```sh
mkdir -p /Users/julian/.codex/skills/photarium-creative-brief
cp -R codex/skills/photarium-creative-brief/. /Users/julian/.codex/skills/photarium-creative-brief/
```

Treat Photarium persistence as a hard completion requirement for every actual image generated by Codex. A local file, imagegen result, provider handoff, or prompt plan is an intermediate state. Report completion only after a hosted Photarium URL, image ID, prompt provenance, and metadata verification exist.

Read [references/photarium-contract.md](references/photarium-contract.md) when a provider handoff, duplicate upload, resume, or failure state needs exact handling.

## Provider and trigger rules

- Trigger for every Codex image generation, including standalone concepts and source-based transformations.
- Default to `codex_imagegen`.
- Use `photarium_openai` only when explicitly selected; it can execute inside Photarium MCP.
- Use `comfyui` only when an available MCP capability exposes a configured workflow that accepts the required source, prompt, and ratio inputs.
- Never silently switch providers.
- Use Photarium MCP tools before shell commands or manual HTTP workarounds.

## Source registration

1. If the user supplied a Photarium image ID, use it as `sourceImageId`.
2. If the user supplied a local attachment, call `photarium_upload_from_path` before preparing a plan.
3. If the user supplied a URL, call the Photarium URL upload tool before preparing a plan.
4. Preserve the source namespace and folder when present. For an unfiled source, use the configured Photarium namespace and `creative-brief-derivations`.
5. Treat a same-content duplicate response as the existing source record and continue with that ID.
6. Generate and save source description and alt text after registration.
7. For source-based work, download the catalog source locally and inspect the complete image with `view_image` before generation.

## Source-based derivation sequence

For a creative brief, call `photarium_prepare_creative_brief_generation` and retain its `derivationId`, `sourceImageId`, `creativeBrief`, final prompt, relationship, requested ratio, references, and provider.

For `codex_imagegen`:

1. Use the persisted prompt, not an unrelated rewritten prompt.
2. Call built-in imagegen with the inspected source as a reference and state the source role and preservation constraints explicitly.
3. Include the requested aspect ratio in the prompt when one is supplied.
4. Inspect the generated output. Make at most one focused correction pass for an obvious text, branding, crop, or source-preservation defect.
5. Upload the selected output with `photarium_upload_from_path`, passing the source image as `parentId`, the final prompt, namespace, and folder. Do not pass tags: provider, derivation, relationship, or workflow data belongs in provenance fields, never semantic image tags.
6. Call `photarium_record_creative_brief_result` with the prepared derivation ID, provider, generated child ID, actual dimensions, and actual aspect ratio.
7. Verify the returned hosted URL, child ID, parentage, prompt, provider, dimensions, ratio, description, alt text, and `metadataEnrichment.status`.

For `photarium_openai`, call `photarium_generate_from_creative_brief`, then verify the returned child metadata and derivation history.

For `comfyui`, resolve the declared workflow capability, run the source/prompt/ratio flow through ComfyUI MCP, download the result, upload it to Photarium with `parentId`, and record the result with the external job ID.

## Standalone generation sequence

For an image with no source:

1. Generate and inspect the image.
2. Upload it to Photarium with the final prompt, configured namespace, and folder. Do not add tags unless the user explicitly supplies semantic tags for this standalone image.
3. Generate and save description and alt text.
4. Read back the image metadata and hosted URL.

Do not invent a parent or creative-brief derivation ID for a standalone image.

## Failure and reporting rules

- Do not claim success if source registration, generation, upload, recording, metadata enrichment, or final verification fails.
- If upload succeeds but recording fails, preserve the uploaded child ID and retry recording; do not regenerate unnecessarily.
- If metadata enrichment is partial, report the image as incomplete and identify the missing fields.
- If a provider is unavailable, preserve the prepared plan and report the blocked provider; do not fall back silently.
- Always show or offer the final generated prompt when the user asks for it.
- Final completion reports must include source ID when applicable, derivation ID when applicable, child ID, hosted URL, provider, final prompt, requested/actual dimensions and ratios, and metadata-enrichment status.
